# Workspace tools load on demand

The portal shell, sign-in/recovery controls, MFA setup, overview and existing dialogs remain immediately available. Thirteen other workspace pages now use React lazy imports and load when their route is opened: assets, monitoring, sensors, investigations, condition inbox, knowledge, reliability, orders, organization, team, activity, settings and production workspace. Shared modules may load with more than one tool. API authorization and all existing backend behavior remain unchanged.

WorkspaceTool supplies an accessible loading message while the page module is pending. A page error boundary keeps the outer navigation available if a module fails to load or render. Switching to another route clears the boundary's failed state. Reload portal is an explicit recovery action, with a warning that reloading clears unsaved form entries. There is no automatic reload that could erase an open form. Normal navigation keeps the same existing page unmounting behavior.

Vite emits a build manifest for checking the entry's static dependency graph and all dynamic page files. The update installer copies the required assets before switching dist/index.html, retains older hashed assets for already-open sessions, and backs up existing checked source files. This is a frontend-only update: no database migration, server restart, authentication change, rule activation, review decision or maintenance action is needed.

Performance measurements compare initial JavaScript bytes, including static dependencies, with the preceding installed build. Gzip comparisons use the same compression settings on both builds. These are asset-size measurements, excluding CSS, fonts, API payloads, later route chunks and wall-clock page timing. They do not establish a response-time or production-capacity guarantee.

The isolated tests-ui/tool-loading.html harness exercises the actual WorkspaceTool component with a pending lazy import, a deliberately missing module and a healthy tool. Build it from the project with `pnpm exec vite build --config tests-ui/tool-loading.config.ts`, then serve the resulting .theme-backups/tool-loading-qa directory on a local test port. Verify Opening workspace tool, the clear failure/reload message, and recovery by switching to Healthy test tool. This fixture is not part of the portal's production entry. It makes no API calls and uses no live accounts or data.
