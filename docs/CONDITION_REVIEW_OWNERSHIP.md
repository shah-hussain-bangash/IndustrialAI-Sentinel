# Condition review ownership

Condition inbox now shows an Owner column and All owners / Assigned to me / Unassigned filters. Ownership filters run in the database before count and cursor pagination, together with current role, canonical site permissions and review-state filters. An owner who loses site access or an eligible role remains recorded with Reassignment needed on open reviews, or Owner access changed on resolved reviews, rather than silently becoming unassigned.

Review match includes Review ownership. Engineers and administrators may assign, reassign or clear responsibility on an unresolved review. The selected person must currently be an engineer or administrator with canonical membership in the equipment's site. Candidate lists expose names, roles and IDs, excluding credentials and email addresses. Find reviewer by name uses literal case-insensitive text matching and returns at most 100 candidates with a truncation message; narrow the name when needed. Assignment grants no permissions, sends no notification and dispatches no maintenance. Other authorized engineers and administrators may still review the match; ownership is responsibility rather than exclusive authority.

Each assignment requires a 5–1000 character note and the expected assignment version. The application appends owner name/ID (or cleared assignment), actor, timestamp and note with audit evidence. Saved names describe the assignment at that time. A match-row write lock serializes assignments with review resolution and evaluator updates. A selected account-row lock serializes eligibility checks with role/site changes. Concurrent/stale versions are rejected. Idempotency keys replay the original result without duplicating history. Resolved reviews retain their final ownership and reject further assignment changes. History is returned in pages of 50, newest first; current ownership remains separate from historical pages.

GET and POST /api/condition-rules/matches/{match_id}/ownership enforce current role/site permissions. GET supports before_version and reviewer_name. POST accepts owner_id (null to clear), expected_version and reason, and requires the existing session CSRF token and idempotency key. Assignment history has no application update/delete endpoints. Changes to role or site membership after assignment do not expand access; canonical permissions are checked again on every request.

Migration 0015 adds condition_rule_assignments without rewriting existing matches, reviews or deployments. The checked installer stops the server, backs up the application and database, checks the prior schema and restores the database/application on upgrade failure. Existing accounts, MFA, readings and private configuration must remain preserved in upgrade rehearsals. Tests cover lifecycle, idempotency, stale versions, permissions, canonical membership revocation, disabled owners, resolved reviews, history pagination, inbox filters and unchanged rule/maintenance states.

This increment provides local review coordination. External notifications, escalation schedules, complete processing provenance, physical maintenance confirmation and production readiness remain separate work.
