# Controlled maintenance windows — 27 November 2026

Workspace settings > Maintenance windows > Load window draft shows independent planning review and separate activation/cancellation. An administrator explicitly activates an independently approved exact revision with a future start, a reason and confirmation. One activation per plan is supported; an activated plan and its review become immutable. Cancel a scheduled or currently suppressing window if necessary. Use a separate plan for another interval. Overlapping effective windows for the same equipment are rejected. Nothing is automatically approved or activated by installation.

Scope: new saved-condition-rule matches for that equipment only. Both observed time and server processing time must lie in the effective half-open interval [start,end). Activation cannot be retroactive. Cancellation ends eligibility at its server time. Expiry is derived from server time; no background scheduler is needed. Reads show the server time of the check. The monitor page shows equipment-scoped current/scheduled maintenance status and explicit loading/failure states. Refresh it for current status.

Readings remain stored. Existing matches retain normal clearance, quality and gap handling; maintenance alone never closes or resolves them. Human reviews, owners, investigations, demonstration baseline episodes, outbound notifications and physical maintenance are unchanged. Above-limit good-quality snapshots where a new match was prevented are stored with the activation, exact rule revision and reading identities. They are not proof of a sustained condition. Control history is complete (activation and optional cancellation); the UI shows the newest 50 suppression records and an explicit total/omission notice. All evidence remains in the database.

Persistence candidates reset across effective maintenance intervals, including when no reading arrived inside a window. After expiry/cancellation a new eligible high reading starts a fresh persistence sequence. Delayed snapshots processed after the effective interval are not retrospectively suppressed; existing monotonic rule watermarks still reject older evaluation. The same asset lock serializes control with snapshot processing. Suppression does not change threshold settings or active/paused rule deployment.

GET /api/maintenance-windows/drafts/{id}/control is engineer/admin scoped; POST requires administrator, CSRF, idempotency, action activate/cancel, expected_draft_version, expected_review_version, expected_control_version, reason (5–1000 characters) and confirmed:true. Stale versions, past starts, missing/current rejection, repeat activation and invalid cancellation return 409. GET /api/maintenance-windows/status?asset_id is available to signed-in users within their canonical equipment/site access and exposes only window names/states and scope. Activated plans cannot be revised or re-reviewed; exact delivery retries retain their original receipt.
