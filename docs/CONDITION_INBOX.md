# Condition inbox

The **Condition inbox** navigation item opens a fleet review queue at #conditions. Engineers and administrators see rule matches for their current permitted sites, across equipment. The global site selector narrows the queue. Review-status filters are Unreviewed (default), Acknowledged, Resolved and All reviews. Signal state is displayed separately from review state, with equipment/site, saved rule/revision and trigger/end times.

The inbox uses the existing match-review workflow directly. Acknowledgement and resolution still require explicit notes and current server-side role/site access. An active signal cannot be resolved. Reviewing a match does not activate a rule, clear a signal, send email, dispatch work or record maintenance completion. Records that change review state may move out of the current filter; refresh starts at the newest matching records. The selected record's review can remain open so the action result and history stay visible.

GET /api/condition-rules/inbox applies canonical site permissions and review filtering in the database, then returns 50 results in descending created/id order, total_matching for the whole filter, and an optional next_cursor (before_created, before_id). Both cursor fields are required together. Counts and pages are current observations rather than a frozen multi-request snapshot. Refresh after concurrent changes. A cursor is only an ordering position: changing it or reusing one cannot widen the current caller's role/site scope. All authorizations and filters apply again on each request. The UI offers Older matches and Newest matches without an unbounded download.

This is a local review inbox, not email delivery, push notifications or an escalation scheduler. It includes rule-match records, not the separate demonstration-score episode workflow. Deployment freshness, real sensor integration, representative engineering validation and wider operational readiness remain separate work.

Installation replaces checked application source/build files with backups and stops/restarts the server for new backend routes. Database schema remains 0014. Existing drafts, reviews, matches, paused rules, accounts, MFA and private configuration are unchanged. Automated verification covers current review-state filtering, cursor ordering with equal timestamps, role/site isolation, malformed cursor rejection and unchanged signal state.
