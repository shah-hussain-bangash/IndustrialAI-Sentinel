# Independent notification planning review — 27 November 2026

Workspace settings > Notification plans now shows independent review below the selected saved plan. A different administrator from that exact revision's author can approve or reject it with a reason and an explicit planning-only confirmation. Engineers can inspect its decision and complete paginated review history. The exact saved plan name, plan/rule revisions, author, timestamp, reason and planned account identities remain visible; unsaved edits block decisions. No real plan is automatically approved by installation or browser verification.

Planning approval is not email-destination authorization, proof of mailbox ownership, delivery readiness or delivery activation. It sends/queues nothing and grants no site access. Demonstration email addresses do not block planning-only review; the screen labels them separately. Approval requires that the plan uses the current saved rule revision and all planned engineers/admins have current canonical site access. A rejection can still be recorded for an obsolete or ineligible plan. The author cannot review their own revision even as an administrator.

Decisions are append-only and reference the exact plan revision. Saving another plan revision returns that revision to awaiting review; older decisions remain historical. A decision about a saved revision is never rewritten when current account checks or the rule head later change. Those current checks are shown separately and must be revalidated before any future delivery feature. Restored eligibility does not constitute a new review or authorize a destination. No automatic action consumes these planning decisions.

GET /api/notification-plans/rules/{rule_id}/reviews returns the exact saved plan, current rule head, latest global review version, decision for that plan (or null), last historical decision, current recipient checks and 50 events; older events use before_version. POST requires decision approved/rejected, expected_plan_version, expected_rule_version (current rule head), expected_review_version, reason (5–1000 characters) and confirmed:true. Canonical site checks apply to both reads and writes. Writes require administrator, CSRF and idempotency. Plan saves and reviews serialize on the same rule-head row; recipient locks serialize eligibility with account changes. Stale head/plan/review values return 409, self-review 403, extra activation/destination fields 422. Exact retries retain their original receipt.

Schema 0021 adds notification_plan_reviews, with composite references to immutable notification-plan revisions and an actor reference. The checked SQLite installer validates the old schema, stops for a running server, backs up data and application files and creates an empty review table. Existing private configuration and all existing runtime records remain unchanged. Historical migrations are preserved. PostgreSQL rollout and operational notification delivery remain separate work.
