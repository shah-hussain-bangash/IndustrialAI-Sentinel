# Condition match evidence

Opening Review match from Condition inbox or Condition rules now shows Triggering evidence above the existing review controls. Engineers and administrators can inspect the exact linked trigger snapshot, its timestamp and aggregate quality, all four recorded signal values and units, and the exact saved revision used by the match. Settings include channel, high limit, hysteresis clearing limit, persistence and maximum gap, with revision author, date and reason. Match start/trigger/end times and recorded signal state remain distinct from the snapshot timestamp and review progress.

GET /api/condition-rules/matches/{match_id}/evidence checks current role and canonical equipment/site access before returning any evidence. It reads the match's composite rule/revision identity and trigger_reading_id rather than the latest draft or latest equipment snapshot. Inconsistent cross-equipment links return 409 without exposing the referenced reading. Nonfinite legacy signal values return null and display Unavailable. No database writes or notifications occur.

This is a historical trigger snapshot, not a complete recording of the evaluator's persistence sequence. It does not establish current equipment condition, prove physical failure or maintenance completion, or identify the ingestion source. Other signal values are context only. New draft revisions and later snapshots do not replace the linked evidence. Reload evidence reads the record again without clearing an unsaved review note. Evidence errors have their own retry control and do not block the existing review workflow.

No database migration is required: schema remains 0014. Installation backs up checked source/build files; existing accounts, MFA, readings, drafts, deployments, matches and review records remain intact. Tests cover pinned historical references after newer drafts/readings, authorization, canonical site isolation, read-only behavior, inconsistent links and nonfinite legacy values. Broader production readiness, full input-sequence provenance and off-device backups remain separate work.
