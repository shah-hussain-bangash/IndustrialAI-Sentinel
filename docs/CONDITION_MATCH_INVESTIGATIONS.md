# Investigations from condition matches

Review match now includes Linked investigation. An engineer or administrator with current canonical access to the equipment's site may prepare one draft investigation for that match, with a note and optional title. The existing recommendation workflow, independent approval, exact-version/hash approval, and work-order planning/dispatch checks remain in place. Preparation does not acknowledge or resolve the match, change ownership or rule activation, create a work order, send notifications or confirm a physical fault.

The match's exact saved revision, historical trigger snapshot, recorded match state/times and preparation note are copied into condition_origin in the investigation payload and its first recommendation revision. The separately identified fresh snapshot used for analysis is also copied, including timestamp, aggregate quality, four values and units. This captured origin participates in the payload hash and remains preserved when the recommendation/checklist is edited through the existing API. Later readings, draft revisions, assignment changes and signal closures do not silently rewrite captured evidence. The investigation view shows historical trigger and analysis timestamps separately, with expandable captured evidence.

Preparation follows the existing one-hour good-quality telemetry requirement, additionally rejecting nonfinite values/timestamps and timestamps more than five minutes in the future. The most recent equipment snapshot must be usable; the API does not silently fall back to an older good sample. Historical trigger evidence can be old, and is never presented as fresh current condition. It does not prove the full persistence sequence or establish ingestion origin. The deterministic analysis still uses the equipment's separately configured demonstration threshold; the captured matched rule settings remain explicitly identified rather than replacing that analysis configuration.

GET /api/condition-rules/matches/{match_id}/investigation returns the existing linked investigation, or readiness/message for preparation. POST accepts title and reason, with the existing CSRF and idempotency protections. A match-row write lock and the match primary-key link prevent duplicate investigations even with different request keys. The idempotency receipt is checked again after acquiring that lock. Later preparation requests return the existing investigation with created=false, without editing it. Inconsistent cross-equipment links fail closed. The link is not editable or deletable through an application endpoint.

Open linked investigation navigates to #intelligence/{UUID}, reloads permitted investigations with the site selector reset to All permitted sites, and opens that record. Server site permissions still determine what is returned. A missing or unauthorized record displays an unavailable message. Closing the linked record returns to the normal AI investigations route. Initial deep links are supported; malformed IDs do not open a record.

Migration 0016 adds condition_match_investigations. The installer checks source hashes and the stopped server, backs up the application and SQLite database, preserves previous records, and restores both on an upgrade failure. Automated checks cover pinned trigger/revision versus newer evidence, captured payload/hash and edit preservation, duplicate/idempotent creation, role/site/CSRF restrictions, unusable telemetry, independent approval and unchanged match/ownership/work-order states. Local draft preparation is not a production integration or a maintenance dispatch.
